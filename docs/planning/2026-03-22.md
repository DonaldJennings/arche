### F-14: Scene geometry in GPU buffers (~1.5 hours)

**Goal:** Every registered mesh's vertex + index data lives in a device-local storage buffer
accessible to compute shaders. A per-instance buffer holds (transform, mesh offset, material ID).

- [ ] Add `SceneMeshBuffer` struct to `VulkanResourceManager`: one `GpuBuffer` for a flat vertex
      array and one for a flat index array, plus an offset table (mesh name → byte offset + count)
- [ ] In `VulkanBackend::initialise()`, after mesh registration: upload all meshes from
      `ResourceRegistry` into the flat buffers with `VK_BUFFER_USAGE_STORAGE_BUFFER_BIT`
- [ ] Add `InstanceBuffer`: per-instance `{mat4 transform, uint32 meshIndex, uint32 materialId}`
      updated each frame from the `RenderScene`
- [ ] Expose `getSceneMeshBuffer()` and `getInstanceBuffer()` on `VulkanBackend`

**Files:** `VulkanResourceManager.h/cpp`, `VulkanBackend.h/cpp`

### F-15: BVH construction (~2.5 hours)

**Goal:** CPU builds a flat AABB BVH over the scene triangles. Serialised to a GPU storage buffer.
The BVH is the acceleration structure the ray tracer will traverse.

- [ ] New `engine/renderer/Public/BVH.h`:
  - `BVHNode` struct: `vec3 aabbMin`, `vec3 aabbMax`, `int left` (child or -1), `int right`,
    `int triOffset`, `int triCount` — flat array, index-based, no pointers
  - `BVH` class: `build(triangles)`, `getNodes()`, `getTriangles()`
- [ ] New `engine/renderer/Private/BVH.cpp`:
  - Triangle struct: `vec3 v0, v1, v2` + `uint instanceId`
  - Build algorithm: midpoint split on longest AABB axis (SAH is Phase 6 polish)
  - Recursion with depth limit (32), leaf threshold (4 triangles)
- [ ] In `VulkanBackend`: after F-14 uploads meshes, build BVH from the combined triangle list
- [ ] Upload `BVHNode[]` and `Triangle[]` as device-local storage buffers
- [ ] Rebuild and re-upload on scene change (entity added/removed): hook into `WorldSystem` or
      trigger from `EngineCore::tick()` when the scene is dirty
- [ ] Add a `m_bvhDirty` flag — rebuild at most once per frame

**Files:** New `BVH.h`, `BVH.cpp`, `VulkanBackend.h/cpp`

## Notes

- **Lazy mesh upload in drawMesh must stay** for the rasteriser path. The storage buffer
  upload (F-14) is a separate parallel upload at initialise time, not a replacement.
- **BVH world-space triangles**: transform each triangle by its instance's model matrix
  during the CPU build. Simpler than a two-level BVH for now.
- **SPIR-V compilation**: use the same workflow as before —
  `C:/VulkanSDK/1.4.341.1/Bin/glslangValidator.exe -V shader.comp -o shader.spv`
  then convert .spv to `constexpr uint32_t[]` with the Python script.
- The `#include "ray_utils.glsl"` pattern requires passing `-I assets/shaders/compute`
  to glslangValidator.
- If the BVH build takes longer than expected, skip SAH and ship midpoint — it's fast
  to implement and correctness matters more than quality at this stage.
